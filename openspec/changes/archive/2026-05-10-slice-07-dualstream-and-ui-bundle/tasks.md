## 0. Coverage map (analyzer aid — links task groups to spec requirements + design decisions)

Spec requirements covered by group:
- Group 1 covers: Meeting carries optional scheduled start and end timestamps; Migration 0004: scheduled_start_at + scheduled_end_at columns.
- Group 2 covers: Session captures BlackHole and microphone as two parallel streams with independent failure domains; Capture orchestration: two AudioCaptureService instances per stream; Device discovery: name pattern with env override.
- Group 3 covers: ASR runs through one ASRProvider instance per stream with parallel warmup; ASR concurrency: two WhisperProvider instances with parallel warmup.
- Group 4 covers: Session emits stream_stopped when one capture stream fails mid-session; WebSocket message contract for the meeting session; Silence in the audio stream is reported within 30 seconds; New WS message type: stream_stopped; Failure isolation: partial fault tolerance during in_progress.
- Group 5 covers: Pre-flight check rejects session start when BlackHole device is missing; Audio capture writes one WAV file per session under RECORDINGS_DIR; WAV persistence: two mono files per meeting; Pre-flight check: device-exists only (relaxed).
- Group 6 covers: WebSocket message contract for the meeting session (frontend reducer side); useMeetingSession hook reducer extension.
- Group 7 covers: TranscriptPane renders chunks with the meeting's me display name; TranscriptPane visual: left accent border + display name prefix; Capture indicator: two pills side-by-side.
- Group 8 covers: Detail page exposes a layout switcher persisted across sessions; Columns mode renders three panes in a 30/40/30 grid with full-width meta; Stack mode renders the three panes vertically in P-T-A order; Advisor pane shows a placeholder until the tactical advisor capability ships; ProtectedShell exposes a fullBleed prop that disables the centered max-width container; Detail page layout switcher: localStorage-persisted Stack/Columns; ProtectedShell fullBleed prop.
- Group 9 covers: GET /meetings/calendar renders the user's meetings on a month or week grid; Calendar event color reflects meeting status; Clicking a calendar event navigates to that meeting's detail page; Clicking an empty day cell navigates to the new-meeting form with the date pre-filled; Meetings without a scheduled start time appear in a collapsible unscheduled list; Meeting list and calendar view are reachable via reciprocal toggle buttons; Empty calendar shows a localized empty-state message; Calendar view library: react-big-calendar Month/Week; Calendar event click behavior.
- Group 10 covers: Calendar import lives at /calendar/import to disambiguate from the meetings calendar view; POST from-calendar creates a meeting and persists a generated playbook draft (route side); Calendar route: /meetings/calendar with /calendar → /calendar/import rename.
- Group 11 covers: PlaybookPane UI exposes a free-form view, a structured view, and a save action; Playbook editor: TipTap WYSIWYG with markdown round-trip.
- Group 12 covers: implementation contract sub-sections — Behavior — observable end-state; Interface / data shape; Failure modes; Acceptance criteria; Scope boundaries. POST from-calendar creates a meeting and persists a generated playbook draft (server-side scheduled fields populated as part of group 1's repository update).
- Group 13.A covers: Calendar event resource attendees are excluded from counterparty derivation; Calendar import: filter resource attendees.
- Group 13.B covers: Vite WS proxy: silence post-close write errors.
- Group 13.C covers: Detail page shows a use-headphones hint above Start Meeting (slice-7 round 2); Echo loop UX: detail page headphones hint + setup doc callout.
- Group 13.D covers: PlaybookPane UI exposes a free-form view, a structured view, and a save action (MODIFIED back to textarea + react-markdown preview); Playbook editor: textarea + react-markdown preview.
- Group 13.E covers: Columns mode three panes share equal visible height (slice-7 round 2); The web app uses a single coherent design token set; Card, Button, and Alert components have a fixed variant catalog; Detail page columns mode renders balanced panes; All UI strings remain in both locale files (slice-7 round 2 housekeeping); UI overhaul via ui-ux-pro-max; Three columns share equal visible height.
- Group 13.F covers: Round-2 verification (no new spec requirements; runs the test/lint/smoke gates).
