## 0. Coverage map (analyzer aid — links task groups to spec requirements + design decisions)

Spec requirements covered by group:
- Group 1 covers: TacticalAdvisor module exposes a streaming advise() coroutine; Streaming protocol: per-SDK-chunk WS frame, transparent forwarding; TacticalAdvisor signature: pure function, no session held.
- Group 2 covers: Advice context assembly uses the last 60 seconds of transcript and non-empty playbook fields; Context assembly: SQL window + dialogue format + non-empty playbook; Prompt structure: system_instruction + user message, Markdown bullet output.
- Group 3 covers: Advice output language follows the request_advice frame's locale field; Locale: tracked via request_advice.locale field.
- Group 4 covers: Advisor exposes a process-scoped FastAPI dependency; Concurrency: separate AsyncSession for advisor task.
- Group 5 covers: WebSocket message contract for the meeting session (4 new frames); In-flight requests: button-disable, end_meeting cancels in-flight; Advisor errors surface as typed advisor_failed frames without closing the session; request_advice forward-compatibility (Slice 9 chatbox).
- Group 6 covers: AdvisorPane renders chat-style cards with streaming markdown and inline retry; AdvisorPane state: chat-style append, ephemeral, scroll-to-bottom; Error handling: typed advisor_failed frame, mapped error codes.
- Group 7 covers: Advisor pane shows a placeholder until the tactical advisor capability ships (MODIFIED — placeholder retired); PlaybookPane stays read-write during in_progress; LLM reads DB-saved version.
- Group 8 covers: implementation contract sub-sections (Behavior — observable end-state; Interface / data shape; Failure modes; Acceptance criteria; Scope boundaries) + verification.
