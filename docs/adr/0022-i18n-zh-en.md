# ADR-0022: i18n with zh-TW (default) and en

- **Status**: Accepted
- **Date**: 2026-05-06
- **Decider**: Sean

## Context
The user works in 繁體中文 daily and may share or demo the app in English contexts. Hard-coding strings now would force a refactor later.

## Decision
- Use `react-i18next` for frontend i18n.
- Two locales: `zh-TW` (default) and `en`.
- Locale strings live in `packages/web/src/locales/<lang>.json`.
- Backend error messages returned to the UI use stable error codes; the frontend maps codes to localized strings.

## Consequences
- Every new UI string lands in both locale files at the same time.
- Backend stays locale-agnostic; only the frontend handles translation.
- Adding a third language (e.g., Japanese) is one new JSON file plus selector wiring.

## Alternatives considered
- **No i18n** — would lock out the en use case and require a big refactor later.
- **Backend-driven translation** — couples backend to UI concerns.
