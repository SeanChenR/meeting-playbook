- [x] 2.2 實作 `POST /api/meetings/{id}/recordings/offline_upload`（creation）的 happy path 與四種拒絕路徑，**行為**：成功 → 寫入 in-memory session map（`upload_id`、`meeting_id`、`upload_length`、`current_offset=0`、`metadata`）、回 201 + `Location: /api/meetings/{id}/recordings/offline_upload/{upload_id}`；拒絕 → 對應 422/413/422/409 + `error_code`（mimetype 不在白名單 → `unsupported_format`；length 超 max → `too_large`；`actual_started_at` 非 ISO 8601 或晚於 now → `invalid_started_at`；banner 條件不成立 → `conditions_not_met`）。Red tests 五條（happy + 4 拒絕），對應 requirement 同名四個 Scenario。
- [x] 2.3 實作 `HEAD /api/meetings/{id}/recordings/offline_upload/{upload_id}`，**行為**：回 200（或 204）+ `Upload-Offset: <current>` + `Upload-Length: <total>` + `Tus-Resumable: 1.0.0`；不存在的 `upload_id` 回 404。Red test 兩條（新建 session offset=0、不存在 session 回 404），對應 `HEAD before any PATCH returns offset zero` Scenario。
- [x] 2.4 實作 `PATCH /api/meetings/{id}/recordings/offline_upload/{upload_id}`，**行為**：`Upload-Offset` 與 server `current_offset` 不匹配 → 409；匹配 → 把 body bytes append 到 `{OFFLINE_UPLOAD_DIR}/{upload_id}.partial` + 更新 `current_offset`，回 204 + `Upload-Offset: <new>`；當 `current_offset == upload_length` → 觸發下游 `OfflineIngestPipeline.run(...)`。Red tests 四條（offset=0 append 一半、mismatch offset 拒絕且檔案不被截斷、完成 PATCH 觸發 pipeline、append 之後檔案 size 等於 offset），對應 requirement 四個 PATCH Scenario。
